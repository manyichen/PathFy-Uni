# 前端性能基线与按路由豁免

更新日期：2026-08-17

## 1. 当前加载策略

- 首页使用原生 SVG，不加载 ECharts，也不加载 p5。
- ECharts 只在图表接近可视区且存在有效数据时异步加载。
- 登录/注册的白鸟旅程画布只在认证页动态加载；离开认证页后，实例在转场结束时销毁。
- 搜索请求统一防抖；岗位详情与报告公开信息继续使用既有缓存与请求取消机制。
- CI 通过 `pnpm bundle:check` 同时校验总体积、基础业务 JS、两个大型懒加载功能以及首页隔离。

## 3. 大型依赖的边界

| 功能 | 原始大小 | gzip | 加载边界 | 决策 |
| --- | ---: | ---: | --- | --- |
| ECharts + vue-echarts | 532,290 B | 181,754 B | 仅数据图表进入预加载视区 | 保留，首页硬隔离 |
| p5 认证旅程（核心 + 无障碍补丁） | 423,817 B | 128,627 B | 仅登录/注册页 | 保留，首页硬隔离，并按资源组设置预算 |
| Nuxt UI / Vue 公共运行时 | 487,127 B | 163,722 B | 全站公共依赖 | 保留，持续监控 |

预算上调不是无条件放宽：`report-bundle-size.mjs` 会识别 p5 核心及其无障碍补丁，检查资源组的文件数、原始与 gzip 体积，并检查首页是否误加载。基础业务 JS 仍有独立上限，防止把普通增长隐藏到 p5 豁免中。

## 4. 继续观测

- 首页初始 gzip 必须保持在 220,000 B 以下。
- p5 或 ECharts 升级后必须重新生成报告；若识别不到认证转场资源，或拆分超过两个文件，门禁直接失败。
- 正式环境继续采集 LCP、CLS、INP 的 p75；若 Hero LCP 超过 2.5 秒，优先把外部图片迁移为同域 AVIF/WebP。
- 若白鸟转场资源组的 gzip 超过 130,000 B，优先减少导入的 p5 子模块或改为更小的专用渲染实现，不应直接放宽预算。
