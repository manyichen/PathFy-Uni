# 生涯报告异步生成说明

更新日期：2026-08-17

## 目标

报告生成采用“两阶段”协议，避免外部模型耗时阻塞页面：

1. `POST /api/report/generate` 仅计算并持久化基础报告，最长客户端等待 30 秒；
2. 前端立即展示基础报告并调用 `POST /api/report/{id}/enrichment`；
3. 后端线程池执行推荐精排、计划定制、分岗叙事和摘要；
4. 前端每 2 秒调用 `GET /api/report/{id}/enrichment`；
5. 状态变为 `completed` 后重新加载报告；失败时保留基础报告并允许重试。

## 状态与恢复

任务状态保存在 `career_reports.meta_json.enrichment_job`，取值为：

- `pending`：基础报告已创建，尚未入队；
- `queued`：已进入后台执行器；
- `running`：正在调用增强服务；
- `completed`：增强内容已原子合并到报告；
- `failed`：增强失败，可重新启动。

页面离开或刷新不会取消后台任务。重新打开仍处于 `llm_enrich_pending` 的报告时，前端会恢复轮询。连续三次状态请求失败才显示错误；轮询超过五分钟时提示稍后刷新或从历史报告恢复。

排队或运行状态超过 15 分钟视为失联任务，可重新入队。AI 增强合并时只覆盖 AI 管理的字段，并保留用户已经提交的复盘、下月计划和行动完成状态。

## 运维边界

当前每个 Flask/Gunicorn 进程最多并行两个增强任务，HTTP 请求会立即返回，不受 Nginx/Gunicorn 120 秒请求超时影响。任务状态在 MySQL 中共享；进程异常退出时任务不会自动迁移，但 15 分钟后可由用户重试。

如并发量持续增长，应将执行器替换为独立的持久化任务队列和 worker；现有 start/status API 与前端轮询协议可以保持不变。
