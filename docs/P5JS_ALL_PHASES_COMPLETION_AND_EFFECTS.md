## 3. 阶段 0：共享 p5 基础设施

### 3.1 完成内容

- 建立统一 `P5SceneHost.client.vue` 场景宿主；
- 建立共享 p5.js 动态加载器，缓存核心加载 Promise；
- 定义 `update`、`resize`、`setActive`、`setReducedMotion`、`resetView` 和 `destroy` 场景契约；
- 统一接入 `IntersectionObserver`、`ResizeObserver` 和 `visibilitychange`；
- 统一处理像素密度、场景激活、卸载销毁和绘制失败；
- 建立 Canvas 与 DOM 信息分工、低动态模式和无障碍回退原则；
- 建立独立 chunk、首页资源隔离和体积预算检查。

### 3.2 最终效果

阶段 0 本身不新增业务画面，但它让后续所有场景具有一致体验：接近可视区域后才加载、离开视口或进入后台后暂停、尺寸变化时正确重绘、组件卸载后不残留 Canvas 和监听器。

### 3.3 用户价值

- 用户不会因为未访问的可视化承担全部下载成本；
- 低动态用户可以直接查看稳定终态；
- p5.js 加载失败不会阻断页面的核心业务；
- 后续场景不再重复实现一套不一致的运行框架。

## 4. 阶段 1：职业路径星图

### 4.1 完成内容

- 对晋升、横向迁移和指定目标转岗接口补充显式类型；
- 使用纯数据适配器统一多种后端响应格式；
- 合并同名共享岗位节点，保留路径类型、方向和可信度；
- 修复切换当前岗位或目标岗位后旧图数据残留的问题；
- 保留完整列表模式作为精确阅读和失败回退。

### 4.2 最终视觉效果

- 当前岗位作为路径起点；
- 晋升岗位位于上方区域；
- 横向迁移岗位分布在下方扇区；
- 指定目标岗位使用独立高亮；
- 节点之间使用不同语义的连线，并用动态光点强化路径方向；
- 悬停节点时降低无关关系的透明度，使当前路线更容易辨认。

### 4.3 交互效果

- 拖动画布查看较大图谱；
- 以指针位置为中心进行滚轮缩放；
- 点击或通过键盘索引选择节点；
- 一键回到当前岗位；
- 在图谱视图和完整列表之间切换。

### 4.4 数据边界

图谱只表现后端返回的真实岗位和路径关系，不根据标题自动补造行业、晋升或推荐关系。精确岗位说明和可信度由 DOM 面板提供。

## 5. 阶段 2A：画像证据汇聚

### 5.1 完成内容

- 审计材料摘要、八维能力和贡献记录字段；
- 建立 `explicit` 与 `overview` 两种真实性模式；
- 将材料、画像核心和八维能力转换为统一场景数据；
- 新画像生成或手动重播时播放一次汇聚动画；
- 保留原有 ECharts 八维雷达图和完整画像说明。

### 5.2 最终视觉效果

- 左侧材料节点代表简历、项目、竞赛和作品等来源；
- 中央画像核心承担材料汇聚终点；
- 八维能力节点环绕画像核心排列；
- 光点沿材料到能力的曲线汇聚，最多生成 140 个粒子；
- 真实贡献关系使用更清晰的连接线，概览映射使用更弱的虚线；
- 场景约 2 秒后停止循环并保留最终结构。

### 5.3 交互效果

- 新画像生成后自动播放一次；
- 用户可点击“查看形成过程”重播；
- 历史画像恢复时仍显示一致的材料与能力摘要；
- Canvas 失败时雷达图、分值、优势和改进建议继续可用。

### 5.4 数据边界

只有接口明确提供材料到能力的贡献记录时，页面才展示为“真实贡献”。字段不足时明确标记为“形成过程概览”，不把动画解释成模型精确归因。

## 6. 阶段 2B：人岗匹配张力场

### 6.1 完成内容

- 统一个人能力与岗位要求的八维分数；
- 兼容 0～1 和 0～100 两种数据范围；
- 将差距划分为缺口、基本均衡和能力余量；
- 建立稳定的岗位切换键，避免新旧岗位形状混用；
- 保留原有 ECharts 雷达图、推荐理由、风险和岗位详情。

### 6.2 最终视觉效果

- 青色多边形表示个人八维能力；
- 紫色多边形表示当前岗位八维要求；
- 八条连接分别表示每个能力维度的张力；
- 颜色和长度共同区分缺口、均衡和余量；
- 切换岗位时，要求形状从旧岗位平滑过渡到新岗位；
- 单次过渡约 1.05 秒，稳定后停止绘制。

### 6.3 交互效果

- 岗位选择变化会直接驱动场景更新；
- 用户可手动重播当前岗位的张力展开过程；
- 精确差距仍可通过雷达图和 DOM 数据表阅读；
- 减少动态效果时立即显示最终对比结果。

### 6.4 数据边界

张力场只根据两组真实八维分数计算方向和强度。它是差距方向概览，不替代精确数值，也不会把缺失的可选字段补造成匹配结论。

### 7.2 最终视觉效果

- 四个偏好维度共同控制纹样的旋向、谐波、锐度和对称性；
- 11 层闭合轮廓构成类似视觉指纹的稳定图案；
- 中心显示 MBTI 类型和稳定签名；
- 新测评完成后播放约 1.12 秒的一次性生成动画；
- 历史记录恢复时直接显示相同终态，不重复随机生成。

### 7.3 交互效果

- 测评提交成功后生成指纹；

## 9. 阶段 4A：岗位星群

### 9.1 完成内容

- 审计岗位列表中的 ID、名称、公司、地点、薪资和八维要求字段；
- 使用真实地点建立分组和颜色图例；
- 将八维岗位要求投影为二维位置；
- 根据八维要求均值控制节点大小；

- 与现有岗位详情弹层、筛选、排序、分页和 AI 助手结果联动。

### 9.2 最终视觉效果

- 同一地点的岗位形成同色星群；
- 岗位在八维能力投影空间中分布；
- 节点大小表示岗位要求均值，不表示个人匹配度；
- 同地点的相近岗位以细线连接；
- 星群建立动画约 0.88 秒，完成后停止循环；
- 悬停和选择时强化当前节点，并保留可读提示。

### 9.3 交互效果

- 岗位列表仍是默认视图；
- 用户选择“星群”后才异步加载场景；
- 点击 Canvas 节点或 DOM 岗位按钮会打开原有岗位详情；
- AI 助手返回新结果时，已打开的星群同步切换结果边界；
- 返回列表后销毁 Canvas，继续使用原筛选和分页。

### 9.4 数据边界

星群只显示当前列表页或 AI 助手当前返回的岗位，不额外请求隐藏结果。页面不根据标题猜测行业，不把节点大小或距离描述为推荐分、排名或个人匹配度。

## 11. 全站形成的统一效果

完成全部阶段后，p5.js 的定位已经统一为“解释关系和过程的视觉增强层”，而不是精确业务信息的替代层：

| 信息类型 | 主要承载方式 |
| --- | --- |
| 关系、流向、形成过程 | p5.js Canvas |
| 精确分值、岗位名称、时间、说明 | DOM、表格和 ECharts |
| 键盘与读屏操作 | DOM 索引和按钮 |
| 动画加载失败 | 保留原页面业务功能，仅视觉层降级 |
| 低动态偏好 | 直接显示稳定终态或提供手动浏览 |
| 页面离屏或进入后台 | 暂停循环和自动引导 |
| 组件卸载 | 销毁 p5 实例、定时器和监听器 |

各业务场景都遵循“真实字段先于视觉推断”的原则。接口没有提供的信息不会因为 Canvas 更适合表现而被前端补造。

## 14. 最终结论

p5.js 全站增强方案的 8 个实施单元已经全部完成。当前网站已经形成从职业方向、画像证据、人岗差距、人格特征、报告执行、岗位探索到首页流程理解的一套统一视觉语言，同时保留原有 DOM、ECharts 和业务入口作为精确信息与无障碍基础。

后续建议不再默认增加新的常驻 Canvas，而应优先通过真实用户反馈验证现有场景是否提升理解效率、模块进入率和行动完成率。新一轮视觉调整仍需遵守真实数据、按需加载、有限动画和完整回退四项边界。
