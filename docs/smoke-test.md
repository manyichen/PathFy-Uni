# PathFy-Uni 发布前冒烟测试清单

更新日期：2026-08-15

关联方案：`docs/FRONTEND_ITERATION_ROADMAP.md` Iteration 0

发布、合并主线或完成一个前端迭代后执行本清单。自动化测试覆盖常见确定性场景，本文补充真实后端、外部服务和人工体验检查。

## 1. 前置条件

- 后端：`python run.py`，默认 `http://127.0.0.1:5000`；
- 前端：`pnpm dev`，默认 `http://127.0.0.1:4321`；
- MySQL、Neo4j 已启动并完成迁移；
- 至少准备一个普通账号、一个管理员账号；
- 需要验证 AI/OCR 时，测试环境已配置对应密钥；
- 浏览器 DevTools Console 和 Network 面板保持打开。

## 2. 自动化门禁

```powershell
cd frontend
pnpm typecheck
pnpm test
pnpm test:e2e
pnpm generate
pnpm bundle:check
pnpm experiment:ssr
pnpm experiment:ssr:test
pnpm test:integration

cd ..\backend
python -m pytest tests/ -q
```

Iteration 7 起，`bundle:check`、SSR/SSG 静态内容检查、hydration/fallback、自动化 WCAG 扫描和浏览器到 Flask 的集成链路均纳入质量体系，任何必需门禁失败都应阻止发布。集成链路在 CI 中先以 nightly/手动任务运行，发布前必须取得最近一次通过记录。已批准的 JavaScript 1 MB 目标豁免见 `docs/FRONTEND_PERFORMANCE_BASELINE.md`；若需调整硬上限，必须在发布记录中写明失败项、影响和恢复日期。

## 3. 基础设施与认证

| # | 操作 | 预期 |
|---|---|---|
| A01 | `GET /api/health` | `ok: true`；包含 `Cache-Control: no-store`、`X-Content-Type-Options: nosniff` |
| A02 | 注册新用户 | 成功后进入目标页或首页，不重复注册 |
| A03 | 使用正确账号登录 | 保存认证状态，刷新后仍登录 |
| A04 | 使用错误密码登录 | 显示后端可读错误，不清空输入的用户名 |
| A05 | 未登录直接访问 `/profile` | 跳转 `/login?redirect=...` |
| A06 | 普通用户访问 `/graph-admin` | 返回首页，不展示管理数据 |
| A07 | Token 失效后发起 API 请求 | 清理认证缓存并跳转登录，保留 redirect |
| A08 | 点击退出 | 先二次确认；确认后清理当前用户及 guest 工作区缓存 |

## 4. 页面状态矩阵

所有核心页面至少检查“成功、空、加载、失败、未登录”五种状态。无法在真实环境稳定触发的异常使用 Playwright Mock 验证。

| 页面 | 成功状态 | 空状态 | 加载状态 | 失败状态 | 未登录 |
|---|---|---|---|---|---|
| `/profile` | 上传材料后显示八维雷达、评价与分析 | 无画像时显示生成引导 | 上传/恢复有明确 loading | 历史接口失败仍可使用页面；上传失败保留表单 | 跳转登录 |
| `/personality` | 完成测试后显示 MBTI 和详细结果 | 未开始时不提前展示题目 | 题目和提交有 loading | 题目失败/提交失败有可读提示 | 跳转登录 |
| `/jobs` | 列表、详情、助手和会话可用 | 无岗位显示空状态 | 岗位与助手分别 loading | 列表失败、助手失败互不拖垮 | 跳转登录 |
| `/match` | 显示排序结果和能力对比 | 无结果提示先选择画像 | 匹配过程显示 Skeleton | 历史/匹配失败保留筛选和旧结果 | 跳转登录 |
| `/graph` | 晋升、横向和目标差距按需展示 | 未选岗位显示引导 | 三类路径请求有 loading | 单类路径失败不造成整页白屏 | 跳转登录 |
| `/report` | 生成、增强、复盘、打卡、导出可用 | 无报告时显示配置引导 | 生成/enrich/导出状态可区分 | 匹配历史失败显示在弹窗；生成失败保留目标 | 跳转登录 |
| `/account` | 偏好载入并可保存 | 服务端无偏好时使用默认值 | 页面与保存有 loading | 保存失败不伪装成功 | 跳转登录 |
| `/graph-admin/**` | Dashboard、任务、变更、设置可用 | 无任务显示创建入口 | 列表和详情有 Skeleton | 403/500 显示错误且不执行危险动作 | 未登录跳登录，普通用户回首页 |

## 5. 核心业务链路

### 5.1 能力画像

| # | 操作 | 预期 |
|---|---|---|
| P01 | 上传一份简历或输入补充文本 | 返回 `resume_id` 和八维分数 |
| P02 | 混合上传多份允许类型材料 | 文件列表可删除；材料来源显示正确 |
| P03 | 缺少姓名、专业或材料提交 | 前端阻止并指出缺失内容 |
| P04 | 从历史画像恢复 | 姓名、专业、雷达和详细分析同步更新 |
| P05 | 刷新页面 | 优先恢复服务器最新画像；接口失败时可回退本地缓存 |

### 5.2 性格测试

| # | 操作 | 预期 |
|---|---|---|
| T01 | 打开页面但不开始 | 题目保持折叠 |
| T02 | 开始、前进、后退、修改答案 | 进度和选项保持一致 |
| T03 | 未答完尝试提交 | 阻止提交并给出提示 |
| T04 | 完成提交 | 显示 MBTI、优势和推荐岗位 |
| T05 | 重新测试 | 清理当前答案，不清理认证和其他工作区 |

### 5.3 岗位与匹配

| # | 操作 | 预期 |
|---|---|---|
| J01 | 搜索、排序、随机浏览岗位 | 列表和分页正确更新 |
| J02 | 打开岗位详情 | 公司、地点、薪资、能力要求和来源可查看 |
| J03 | 发起岗位助手会话 | 用户/助手消息正确排列，失败可读 |
| M01 | 选择画像并开始匹配 | 返回排序岗位，匹配分不为 `NaN` |
| M02 | 切换稳妥/冲刺和 AI 精排 | 请求参数和结果解释对应策略 |
| M03 | 加载历史匹配 | 恢复结果；接口失败不显示成“暂无记录” |
| M04 | 刷新页面 | 恢复当前用户的匹配缓存，不串到其他用户 |

### 5.4 生涯报告闭环

| # | 操作 | 预期 |
|---|---|---|
| R01 | 从匹配历史导入目标 | 自动关联画像和最多 5 个目标 |
| R02 | 搜索、随机浏览或完整岗位库手选 | 目标去重，最多 5 个，`job_id` 有效 |
| R03 | 生成报告 | 基础报告应在 30 秒内出现；页面显示后台增强状态，不能持续阻塞生成按钮 |
| R04 | AI 增强完成/失败/刷新 | 成功后自动更新；失败保留骨架并可重试；刷新后继续读取任务状态 |
| R05 | 查看历史报告 | 目标、计划、复盘和图表恢复 |
| R06 | 提交月度复盘 | 指标和下月计划更新，不产生裸 500 |
| R07 | 勾选行动项 | 保存成功；失败时 UI 回滚 |
| R08 | 加载岗位公开信息 | 单目标独立加载，失败不影响整份报告 |
| R09 | 导出 PDF | 下载文件名和内容正确，失败提示可读 |
| R10 | 清空工作区 | 必须二次确认，只清理报告工作区 |

## 6. 图谱管理

| # | 操作 | 预期 |
|---|---|---|
| G01 | 管理员打开 Dashboard | 图谱版本、质量、队列和最近任务可见 |
| G02 | 创建更新任务 | 进入任务详情；创建时不直接修改 Neo4j |
| G03 | 查看变更集 | 摘要、分组、能力差异和风险标记可审阅 |
| G04 | 确认任务 | 二次确认后整单应用，状态和版本更新 |
| G05 | 拒绝/取消任务 | 必须填写适当原因，状态更新且不写图谱 |
| G06 | 图谱被锁定 | 显示锁定任务入口，不允许并发危险写入 |
| G07 | 发布系统设置 | 产生新 revision，历史版本可载入但不直接覆盖 |

禁止使用旧 `/api/graph/import-jobs`、`/sync/*`、`/generate/*` 操作生产图谱。

## 7. 响应式、主题与可访问性

在 1440×900、768×1024、390×844 三档检查：

- 无横向滚动条；
- Header 和移动菜单不遮挡主要操作；
- Modal 不超出视口，内容可滚动；
- Light/Dark 和至少两个 hue 下文字可读；
- `prefers-reduced-motion` 下无强制大动画；
- 仅用键盘能完成登录、导航、开关 Modal 和提交主要表单；
- 图表之外存在文字解释，不只依赖颜色；
- 浏览器缩放到 200% 后核心功能仍可操作。
